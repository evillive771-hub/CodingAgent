# ADR-0018：会话分叉与文件修改恢复

## 状态

Accepted

## 背景

持续对话需要从历史回合尝试另一条思路，但复制 transcript 不会撤销工作区代码。使用
`git reset --hard` 会覆盖用户未提交修改，也无法区分 Agent 写入和外部编辑，因此不能作为对话恢复
机制。

## 决策

- `/fork <new-session> [turn]` 原子复制指定回合之前的用户/Agent 最终消息，并为复制回合生成新
  `run_id`、保留 `origin_run_id`；源 transcript 不变，目标必须不存在；
- 分叉只复制对话历史，不复制 Plan、Task DAG、Steering、权限、后台任务或模型内部 transcript；
- `ToolExecutor` 在逐文件锁内捕获 UTF-8 文本工具的前后完整快照并追加到受保护 Mutation Journal。
  日志落盘失败时立即恢复写入前快照并使工具失败；
- `/rewind <new-session> <turn>` 在源/目标会话锁内，先对选中回合之后的文件记录逆序恢复，再原子
  创建分叉 transcript；创建失败可以用同一恢复 ID 安全重试；
- 恢复前锁定全部目标文件并进行全量预检。当前内容不是任一日志边界、跨回合快照链不连续或重复
  恢复后又出现外部修改时，整个操作失败，不进行部分恢复；
- 进程和外部风险工具在启动前追加不可逆 Effect 记录。选中回合包含此类记录时，恢复保守拒绝；
- 本能力不调用 Git reset，不触碰生产发布、Git 推送、Teambition 写回或部署。

## 结果

用户可以保留原会话并建立独立对话分支，也可以安全撤销 Agent 文件工具在后续回合产生的已记录
文本修改。该能力不是通用工作区快照：二进制文件、超出限制的文件、外部进程副作用和用户编辑均不
会被猜测性覆盖。Journal 含完整文件内容，只存放在受工具路径策略保护的运行目录，不进入模型上下文。
