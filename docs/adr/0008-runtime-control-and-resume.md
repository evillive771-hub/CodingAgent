# ADR-0008：单 Agent 运行时控制与工作流恢复

## 状态

已接受。

## 背景

持续对话需要允许用户在 Agent Loop 运行期间改变方向，同时长时间验证和交付步骤需要跨进程恢复。
直接取消任意协程或把部署能力暴露给模型，会破坏工具调用配对、权限合同和外部副作用的幂等性。

## 决策

1. 保持单 Agent Loop；用持久化 `SteeringInbox` 在安全边界消费 `steer / next / interrupt`。
2. 用版本化 `PlanManager` 表达方向变更，旧计划标记 `superseded` 后必须显式重建。
3. 模型调用期间到达的控制消息取消尚未执行的工具调用，并为每个调用写入结构化取消结果。
4. Hook 使用宿主注册的异步 `HookBus`；PolicyEngine 先于 `PreToolUse` Hook 执行，Hook 不得提权。
5. 后台任务只接受任务合同中的精确验证命令，不接受 Shell 字符串，也不承载部署或 Git/TB 写入。
6. 上下文压缩前保存完整 transcript，大型输出按哈希归档；压缩保护合同、计划、转向和验证状态。
7. `DeliveryWorkflow` 从原子 Checkpoint 恢复，逐个副作用保存回执并复用稳定幂等键。
8. 生产发布继续由独立系统和人工审批完成，不属于 Coding Agent 或恢复逻辑。

## 结果

用户可以在同一终端持续对话和转向，旧方向不会在控制消息到达后继续修改代码。耗时验证不会阻塞
输入循环，宿主重启后状态可解释。交付恢复会跳过已持久化步骤或以相同幂等键安全重试，但要求外部
适配器遵守幂等合同。当前结构保留未来将任务执行器替换为多 Agent 调度器的边界，而不提前引入
共享写工作区的并发复杂度。
