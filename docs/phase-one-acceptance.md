# 阶段一实现与验收

## 软件交付范围

阶段一的目标是由人工任务合同触发单项目、单分支、单测试设备的串行闭环。当前实现包括：

1. 校验 JSON 任务合同，并从已有本地 Git checkout 创建冻结基线的隔离 worktree；
2. 在受策略约束的 Agent Loop 内修改代码，之后由确定性 Stop Gate 执行合同中的验证命令；
3. 使用精确 argv 执行构建命令，冻结制品清单、文件哈希、日志和失败证据；
4. 通过强制主机密钥校验的 SFTP 上传 NFS，并仅调用配置冻结的 SSH 入口完成切换和健康检查；
5. 使用 Playwright 采集页面截图、Trace、视频、控制台错误和失败请求；
6. 生成绑定合同、代码差异、制品、部署与浏览器证据哈希的人工审批包；
7. 验证失败或人工拒绝时回滚。回滚失败会持久隔离设备并阻断后续发布；人工恢复必须有审批归属且健康检查通过；
8. 全流程写入 append-only JSONL 事件和原子 Checkpoint，可使用同一 `run_id` 安全恢复；
9. 阶段一批准只结束测试交付，不执行 Git push、MR/PR、Teambition 写回或生产发布。

阶段一入口会实时显示阶段和 Agent/工具状态，但不会把工具输出打印到进度行，避免凭据进入终端日志。
只有 `completed` 使用成功退出码；失败、拒绝、回滚和隔离均使用非零退出码。

## 自动化验收证据

- 构建、部署、Playwright、配置、设备隔离和进度输出均有独立单元测试；
- 阶段一集成测试使用真实构建与制品冻结逻辑，以及协议边界内的远端和浏览器替身，验证完整审批闭环；
- Playwright 适配器可使用真实 Chromium 执行本地页面冒烟测试；
- 工作流测试覆盖验证失败回滚、结构化回滚证据和崩溃后恢复；
- 项目交付门禁为 `uv run pytest` 与 `uv run ruff check .`。

## 需要用户环境完成的最终演练

代码仓库不能替代企业网络中的 NFS、SSH 账号、主机密钥、域名和 Nginx，因此真实设备联调不是一个可在
本地伪造后宣称通过的软件功能。准备 Linux/WSL2 测试设备后，按 `examples/phase1/README.md` 安装固定
设备入口并填写配置，运行一个真实 Bug 合同。最终演练应保存以下证据：SFTP 远端哈希、切换和健康检查
回执、Playwright 截图/Trace/视频、审批记录，以及一次受控拒绝或失败后的回滚记录。

WSL 降级实验室上已经执行并归档过一次完整演练（真实模型修复 → 受控构建 → SFTP 部署 → Playwright
验证 → 批准与拒绝两条路径），证据清单和独立复核见
[阶段一演练记录（2026-09-10）](phase-one-drill-20260910.md)。该记录使用本地目录代替 NFS 挂载，
**不能作为真实 NFS 验收证据**，上面要求的最终演练仍需在 Linux 测试设备上完成。
